1. 大前提 — Claude Codeとフォルダの関係

Claude Codeを使う上で、一番大事な概念がフォルダです。

Claude Codeは、起動したフォルダの中にあるファイルを全部読めます。
逆に言えば、フォルダの外にあるファイルは読めません。

つまりこういうこと：

「どのフォルダで Claude Code を起動するか」＝「AIが何を知ってるか」が決まる。

例えば：

  • デスクトップで起動 → デスクトップのファイルしか見えない。AIは何も知らない
  • このキットのフォルダで起動 → CLAUDE.md、mind.md、memory.md を自動で読む。AIがあなた専用の動きをする

CLAUDE.md とは？

フォルダの中に CLAUDE.md というファイルがあると、Claude Code は起動時に自動で読みます。
読んだ内容をルールとして守ります。

つまり CLAUDE.md は「AIへの業務マニュアル」です。

新しいスタッフに「うちではこうやって仕事してね」と渡すマニュアルと同じ。
ただし人間と違うのは、AIは毎回このマニュアルを完璧に読んでくれること。

ポイント： CLAUDE.md は毎回自動で読まれる。書いたことは毎回守られる。だからここにルールを書くのが最強。

じゃあ問題は何？

CLAUDE.md に書いたルールは毎回読まれる。でも「会話の中で学んだこと」は毎回消える。

例えば：

  • 「うちの担当は田中さんだよ」と教えた → 次のセッションでは忘れてる
  • 「そのやり方ダメって言ったでしょ」と直した → 次のセッションでまた同じことする
  • 「昨日ここまで進んだよね」 → 「何の話ですか？」

CLAUDE.md だけでは解決しない。会話で生まれた知識を自動で保存する仕組みが必要。

それがこのスターターキットです。

2. このキットは何か

一言で言うと：「使うほど賢くなるAI」を実現するフォルダ一式です。

仕組みはシンプル：

  1. あなたが普通にClaude Codeを使う
  2. セッション終了時に「ここまで」と言う
  3. AIが学んだことをファイルに自動で書く（memory.md）
  4. 次回起動時にそのファイルを自動で読む
  5. → 前回の続きから始まる。同じミスをしない。

あなたがやることは2つだけ：

① フォルダを置いてClaude Codeを起動する

② セッションの終わりに「ここまで」と言う

残りは全部自動です。

フォルダ構造

my-project/ ← 好きな名前に変えてOK
├── CLAUDE.md ← AIの業務マニュアル
├── ai-export-prompt.md ← 別AIから引き継ぐ時に使う
├── roles/
│   └── assistant/
│       ├── mind.md ← AIの性格・行動原則
│       └── memory.md ← AIの記憶（自動で育つ）
├── knowledge/ ← 長期記憶（自動で育つ）
├── files/ ← 画像・参考資料の置き場
└── .claude/
    └── skills/ ← 自動で動くスキル4つ
        ├── setup/ ← 初回セットアップ
        ├── session-wrap/ ← セッション終了時の記録
        ├── task-log/ ← 緊急セーブ
        └── status/ ← 成長度チェック

3. 全ファイル解説

1つずつ、「何のためにあるか」「なぜ必要か」を説明します。

CLAUDE.md
AIの業務マニュアル
なぜ必要？ → これがないとAIは何のルールも知らない状態で動く
起動時に自動で読まれるファイル。中には以下が書いてある：
  • 初回起動ルール： mind.mdがまだ未設定なら /setup を自動実行する
  • セッション開始ルール： 毎回 memory.md と knowledge/ を読んでから仕事を始める
  • メモ魔ルール： 「こういう時は必ず記録しろ」という6つのトリガー
このファイルは基本的に触らなくてOK。仕組みの土台。
roles/assistant/mind.md
AIの性格・行動原則
なぜ必要？ → 同じAIでも「簡潔に話せ」と「丁寧に説明して」では全然違う動きになる
あなた好みのAIにするための設定ファイル。
手書き不要。初回起動時の /setup で自動生成される。
使い続けると「こう話せ」「これするな」が自動で追記されていき、あなた専用の性格に育つ。
roles/assistant/memory.md
AIの記憶（短期記憶）
なぜ必要？ → これがないとAIは毎回全部忘れる。毎回同じ説明、毎回同じミス
空の状態からスタート。セッション終了時に「ここまで」と言うと、AIが自動で以下を書き込む：
  • 今回学んだこと（ダメ出しされたこと、新しくわかったこと）
  • タスクの進捗（何が終わって、何が途中で、次に何をすべきか）
  • 次回への申し送り
次に起動した時に自動で読み込まれる。だから「前回の続き」から始まる。
knowledge/
AIの長期記憶
なぜ必要？ → memory.mdは日々の記録で流れていく。何度も出るパターンは「確定知識」として永久保存すべき
空フォルダからスタート。
memory.md に同じパターンが3回出ると、AIが自動でここにファイルを作って移す。
例：mistakes.md（やっちゃダメなこと集）、tips.md（うまくいくやり方集）。
memory.md が「ノート」なら、knowledge/ は「教科書」。
files/
画像・参考資料の置き場
なぜ必要？ → VS Codeのチャットでは画像を直接貼り付けできない
スクリーンショットやPDF等をここに置いて、「files/の画像見て」と伝える。
Claude Codeがファイルを読み取って対応してくれる。
ai-export-prompt.md
別AIからの引き継ぎ用プロンプト
なぜ必要？ → ChatGPTやGeminiで育てた好み・ルールがあるなら、ゼロからやり直すのは無駄
中にプロンプトが入ってる。それを今使ってるAIに貼り付けると、あなたの好みを要約してくれる。
その出力を /setup に貼り付けると、最初から精度の高い mind.md が生成される。
別のAIを使ってない人はスキップしてOK。

スキル（.claude/skills/）

スキルは「特定の言葉を言うと自動で動くプログラム」です。手動で呼び出す必要はありません。

/setup
初回セットアップ
いつ動く： 初めてClaude Codeを起動した時に自動で始まる
何をする： 4つの質問であなたの仕事・好み・ルールを聞いて、mind.md を自動生成する
所要時間： 5分
/session-wrap
セッション終了時の記録
いつ動く： 「ここまで」「まとめて」「振り返り」と言った時
何をする： 学んだこと + タスク進捗を memory.md に記録。knowledge/ への昇格判定もやる
これが「記憶する仕組み」の核心。
/task-log
緊急セーブ
いつ動く： 「中断」「セーブ」と言った時
何をする： 今やってることと再開手順だけを素早く記録する
session-wrap の軽量版。急に止めなきゃいけない時用。
/status
成長度チェック
いつ動く： 「/status」「育ち具合」と言った時
何をする： 行動原則の数、記憶の件数、レベル（Lv.1新人 → Lv.5右腕）を表示
育ってる実感が持てる。

4. 使い始め方

1 フォルダ名を変える

my-project を自分の仕事の名前に変える。
例：sales-ops、accounting、blog-management

2 Claude Code を起動する

そのフォルダの中で Claude Code を開く。
mind.md がまだ未設定なので、/setup が自動で始まる。

3 4つの質問に答える

AIがこう聞いてくる：

AI
4つだけ教えてください。

① お仕事は？ Claudeに何を手伝って欲しいですか？
② AIにイラッとしたことは？ これが一番大事です。
③ どんな感じで話して欲しい？ 丁寧 / フランク / 簡潔 / 壁打ち
④ これだけは絶対やるなってことある？

答えるだけで mind.md が自動生成される。手書き不要。

② が一番大事な理由：

「長い」「聞いてばっかり」「毎回忘れる」— あなたの不満は、あなたの「AIはこうあるべき」の裏返し。
これが mind.md の行動原則（AIの性格）に変換される。

4 何か1つ仕事をする

いつも通り何でもOK。普通に使う。

5 「ここまで」と言う

これだけ。AIが自動で memory.md に記録する。
次に起動した時、前回の続きから始まる。

5. AIが育つ話し方

特別なことは何もない。思ったことをそのまま言うだけ。
ただし、言い方によって育ち方が変わる。

ダメ出しする → 行動原則が増える

AI
分析結果をまとめました。まず市場動向から説明すると...
あなた
長い。結論だけ先に言って
→ mind.md に「結論ファーストで話せ」が追記される

「覚えておいて」と言う → 即記録される

あなた
覚えておいて、A社の担当は田中さん。メールより電話が好き
→ memory.md に即記録。次にA社の話が出たら自動で反映

理由を添える → 深い学びになる

あなた
この提案ダメ。うちの業界ではそのやり方は法的にアウトだから
→ 「なぜダメか」が knowledge/ に記録される。二度と同じ提案をしない

「いいね」も言う → 刺さったポイントが記録される

あなた
この表形式いいね。次からもこの形式で出して
→ 好みのフォーマットが記録される。次回から同じ形式で出してくる

育たない話し方：

「うーん、まあいいか...」
→ 何も記録されない。違和感があったら遠慮なく言う。ダメ出しは最高の教育。

覚えておきたい3つの言葉

「ここまで」 セッション終了。学び + タスクを記録する
「覚えておいて」 即記録。事実・ルール・好みなんでも
「/status」 今どのくらい育ったか確認

6. 育った先の姿

1日目

/setup が完了。mind.md に行動原則が3〜5個。memory.md は空。
まだ何も知らない新人。でも「あなた好みの話し方」は最初からできる。

1週間後

memory.md に記録が溜まり始める。
「前回ここまでやりましたよね」「A社の田中さんですね」が自動で出てくる。
同じ説明を2回する必要がなくなる。

1ヶ月後

mind.md の行動原則が10個を超える。knowledge/ にファイルが生まれる。
あなたの仕事の癖、好み、NG を全部知ってるアシスタントが完成する。
「おはよう」と言うだけで、今日やるべきことを提案してくる。

最初から完璧にする必要はありません。

フォルダを置いて、普通に使って、「ここまで」と言う。
それだけで、AIは勝手に育ちます。
